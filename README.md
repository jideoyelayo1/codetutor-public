# Codetutor

An iPhone and iPad app for learning and retaining programming languages through guided lessons, spaced recall and code you can run.

## What it does

Codetutor is for developers who want to keep languages they already know sharp and learn new ones properly. It bundles 13 tracks (Python with NumPy, pandas, scikit-learn and PyTorch; C++; Rust; OCaml; Lean 4; Bash; C#; Go; JavaScript) with 1,311 lessons, 3,131 recall cards and a bank of 1,088 C++ problems and 26 quizzes. Each lesson has worked examples, a checkpoint and recall cards scheduled with FSRS 6. A Lab screen edits code and runs Python, Python ML, C++, Rust, OCaml and Lean 4 on a self-hosted execution server. Everything except code execution works offline.

## Architecture

```
iOS app (SwiftUI) ── HTTPS + bearer token ──> gateway (FastAPI) ── private network ──> Piston engine
  bundled curriculum.json, progress on device        auth, limits, verified runtimes          runs the code
```

- The app ships its curriculum as JSON and stores progress, drafts and history on the device.
- The gateway (`backend/`) authenticates requests, enforces limits and forwards code to [Piston](https://github.com/engineer-man/piston); it never runs code itself.
- No LLM or hosted AI service is used at runtime.
- The curriculum is generated by Python scripts in `scripts/`, which also compile and run every example with real toolchains.

More detail: [architecture](docs/ARCHITECTURE.md), [API](docs/API.md).

## Requirements

- macOS with Xcode 27 (Swift 6.4) and an iOS 18 or later simulator or device
- Python 3.11 or later for the gateway (3.13 for the pinned ML runtime)
- For code execution: a Linux x86_64 host running Piston, behind HTTPS

## Setup

### Configuration

1. Copy `backend/.env.example` to `backend/.env`.
2. Set `RUNNER_TOKEN` to a random string of at least 32 characters.
3. Set `PISTON_URL` if the engine is not on `http://127.0.0.1:2000/api/v2`, and `RUNTIME_VERIFICATION` to the record produced by `backend/verify_engine.py`.

See [configuration](docs/CONFIGURATION.md) for every value.

### Run the gateway locally

1. `python3 -m venv .venv && .venv/bin/pip install -r backend/requirements-dev.txt`
2. `set -a; . backend/.env; set +a`
3. `cd backend && ../.venv/bin/uvicorn gateway:from_environment --factory --host 127.0.0.1 --port 8080`

Without a verified engine the gateway starts but offers no runtimes. Deploying the engine is covered in [release](docs/RELEASE.md).

### Run the app in the simulator

1. Open `CodingTeacher.xcodeproj` (the Xcode project and scheme are named CodingTeacher).
2. Choose the **CodingTeacher** scheme and an iPhone simulator, then run.
3. To execute code, open **Settings**, enter the gateway's HTTPS URL and token, and choose **Save & check connection**.

For a device, choose your signing team in Signing & Capabilities.

## Testing

```sh
# App (Xcode 27)
xcodebuild -project CodingTeacher.xcodeproj -scheme CodingTeacher \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' CODE_SIGNING_ALLOWED=YES test

# Gateway
.venv/bin/python -m pytest backend -q

# Curriculum is reproducible, plus the content tooling tests
python3 scripts/make_content.py --check
.venv/bin/python -m pytest scripts -q
```

Six app tests need the offline Rust manuals and fail without them; see [configuration](docs/CONFIGURATION.md#optional-offline-rust-manuals). The `scripts/validate_*.py` checks need each language's toolchain.

## Privacy

Progress, notes and code drafts stay on the device; backups are files you export yourself. Code you run in the Lab, and its input, is sent only to the gateway you configure. Library search sends your query to the GitHub API. The app has no analytics or accounts.
